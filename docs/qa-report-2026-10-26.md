# Agent test round — 2026-10-26

Three independent test agents exercised the planner:

1. **UI tester:** drove the running app in a browser as a planner would, covering all 8 tabs and phone width.
2. **API / security tester:** ran 35 tests against the web layer and reviewed the deployment files.
3. **Engineering-logic tester:** probed calculations, import, fibre allocation, validation and every exporter with edge cases.

Each finding below was verified before fixing. Regression tests for them are in `tests/test_regressions.py`. The suite now runs 43 tests, all passing; it was 25 before this round. Of the security agent's own 35 tests, 30 pass. Of the other 5:
- 3 are deliberate behaviour changes: a missing conflict header now returns 428 instead of 409, a forged photo path is rejected at save, and a test setup save without the header is refused.
- 1 is a false positive: every ReportLab PDF contains the text "/Image".
- 1, the photo sign-in redirect, is now a JSON 401.

## Fixed

### Security
| Finding | Fix |
|---|---|
| PDF text was interpreted as markup, so `<img src=...>` in a project name made the server fetch URLs or embed local files (SSRF). It also caused a 500 on `<` or `&` | All user text is escaped (`exporters/common.markup`) |
| Photo paths: a `Photo.file` such as `../other-project/x.png`, or an absolute path, pulled other projects' photos or any server image into reports | The model accepts only generated photo names. Exporters open only verified images inside the project folder |
| KMZ zip bomb: unlimited decompression | At most 60 MB is ever read; the size header is not trusted |
| Stored XSS: map tooltips rendered KML names as HTML; currency and rule keys were not escaped | Escaped. Added a strict Content-Security-Policy (no inline scripts) and integrity hashes on Leaflet |
| A save without the `X-Base-Hash` header skipped the conflict check | The header is required (428) |
| The UI could conflict with itself during slow saves | Saves are queued one at a time |
| Excel formula injection: text starting with `=` was written as a formula | User text is always stored as text |
| Photo upload checked only the file extension | Verified with Pillow; only real JPEG/PNG accepted |
| 500s on malformed JSON bodies, `max_drop_m=abc` | 400 with a clear message |
| No sign-in rate limit | 10 failures per username and address locks that pair for 15 minutes |
| Backups: a failed `pg_dump` still wrote a "good" file, and rotation could delete all good backups | `pipefail`, atomic rename, newest 3 always kept, `umask 077` |
| A non-approver could carry an approval through restore and revision | A restore returns the design to draft and is recorded; only approvers can record an approved revision |
| Admin creation at start-up hid errors | It reports that the admin already exists, or shows the real error |

### Engineering logic
| Finding | Fix |
|---|---|
| **Crash:** import with two poles at identical coordinates | Fixed sort key |
| **Crash:** PDF with `<` in a note | See markup escaping above |
| A duplicated route point or pole created phantom corners: 4 tension clamps instead of 1 J-hook | Repeated points are merged on import; the pole summary ignores zero-length segments |
| A FAT added after the first allocation was never fed, with no warning | Gets its own splitter unless daisy-chained to a FAT that has one. New `fat_no_splitter` check |
| The alphabetically first POP was used as root even with no cables | The root is the POP / interception closure reaching most of the network |
| A "PON" folder turned FATs into PONs | FAT names take precedence |
| KML export → import lost proposed status, FAT ports, MDU units, crossings and splitters (BOQ −13 %) | ExtendedData is read back. Splitters and crossings are exported. Round-trip BOM now identical |
| CSV import ignored status, ports and FAT columns; `PR FAT-03` became a PR enclosure; `24HPs` became 1 unit; comma-decimal coordinates were misread; duplicate IDs silently overwrote | All handled; duplicates kept and reported |
| One-point cables got accessories; co-located FAT + slack counted twice; splitters were created for unreachable FATs | Fixed |
| Two first-stage splitters at one node: only the first was used | All are fed and used |
| KML without `<Document>`, spaces in coordinates, GPX without lat, non-UTF-8 CSV, title rows above the header | Handled |
| Re-importing the same KMZ duplicated everything silently | Warns |
| Missing checks | Negative BOM quantities, duplicate connection IDs, photos referencing unknown features, near-duplicate equipment |
| Large designs slow: PUT with 20,000 poles took 145 s | 1.9 s, using O(1) self-checking lookups |

## Calibration effect

Removing the phantom corners made pole KP-W 13 match the BOM exactly (3 tension clamps instead of 5). The earlier exact total of 57 had partly been two errors cancelling. On the 49 BOM poles the planner now gives 55 / 26 / 23 / 1 (tension / UPB / J-hook / extension arm) against 57 / 27 / 23 / 1, with 30 poles identical, up from 29. Cable totals are unchanged: 12C −1.6 %, 48C +0.3 %.

## Known limits (not changed)

- The sign-in throttle counter is per process. With 3 gunicorn workers an attacker gets up to about 30 tries per 15 minutes. Use Redis/Memcached as the Django cache for a shared counter.
- Usernames can be checked through Share (200 vs 404). This is needed for sharing; it is visible to signed-in users only.
- Latitude/longitude that are swapped but both in range (e.g. 36.8, −1.3 in Kenya) are corrected on import when most points disagree. The validator does not flag them afterwards.
- KML MultiGeometry lines import as separate cables.
- The Django admin keeps Django's default headers (no custom CSP).
- The superuser password from `.env` is visible to anyone with `docker inspect` access until it is removed from `.env` after first sign-in, as DEPLOY.md instructs.
- FOC-48C (KES 44.578/m) is cheaper than FOC-12C (KES 70/m). These rates come from the V Squared BOQ and should be confirmed by the user.
